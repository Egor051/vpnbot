# Сайт-приманка из бота

Сайт-приманка — статический сайт, который nginx отдаёт на `127.0.0.1:8443`. На него REALITY
в Xray пересылает каждого TLS-клиента, который не свой (`realitySettings.target`), и туда же
проксирует маскировка Hysteria2 (`deploy/hysteria/config.yaml`, `type: proxy`). Поэтому
сканер видит настоящий сайт и по TCP, и по UDP. **«🧙 Мастер настройки → 🌐 Сайт»** заменяет
его архивом, присланным боту, или возвращает предыдущую версию. Раньше для этого запускали
скрипт вручную.

🇬🇧 English version: [site.md](site.md)

Конфигурацию nginx и сертификат выкладка только читает и никогда не пишет. nginx не
перезагружается: файлы он читает на каждый запрос.

## Экран

Только SUPERADMIN. Экран читает `vpn-bot-site status --json` и показывает:

* **где сайт**: каталог (docroot) и домен;
* **живую версию**: sha256 её дерева (12 hex), когда и каким запуском её выложил бот (или
  *выложена не через бота* — с датой самого нового файла), число страниц и файлов, размер.
  Дерево, изменённое после выкладки, помечено 🟡. Это ожидаемо, когда
  `deploy/vpn-bot-decoy-freshen.sh` сдвигает даты на сайте;
* **сохранённые версии** и какую из них вернёт «Откатить»;
* **spiderX**: называет ли `XRAY_SPIDER_X_POOL` страницы сайта (ниже);
* **Hysteria2**: показывает ли её маскировка тот же сайт.

Кнопки:

| Кнопка | Что делает |
|---|---|
| **⬆️ Загрузить архив** | TOTP, затем архив **документом**. Бот кладёт его для root и запускает режим мастера `site`. План распаковывает и проверяет архив в изоляции и показывает, что изменится. **✅ Применить** (снова TOTP) выкладывает. |
| **↩️ Откатить на предыдущую** | Тот же запуск, но вместо архива — новейшая сохранённая версия. |
| **📄 Список страниц** | Страницы живого сайта (`/`, `/about.html`, `/blog/` для `blog/index.html`), по 40 на экран. |

Каждый запуск есть в «📜 История» с логом. В аудит-логе — `wizard_run_*` (сущность
`wizard`) и `site_spider_x_relayout` (ключи, которые запуск переразложил).

## Где сайт

Каталог не зашит в код. Это `root` vhost'а nginx, который слушает `127.0.0.1:8443`
(`/etc/nginx/conf.d/*.conf`, `/etc/nginx/sites-enabled/*`):

* `/var/www/selfsteal` — на хосте, где Xray поставил бот
  ([protocol-install.ru.md](protocol-install.ru.md), `deploy/nginx/selfsteal.conf`);
* `/var/www/anycastedge` (или что указано в его vhost) — на хосте, настроенном руками.
  Установка протокола такой vhost сохраняет.

Домен — `server_name` vhost'а, а если его нет — `HYSTERIA2_SNI`. Это SNI всех проверок.
Helper отказывает, и экран пишет почему, если:

* такого vhost'а нет или их несколько;
* `root` нет, их несколько, в нём переменная или это не каталог внутри `/var/www/`;
* каталог — симлинк;
* vhost ждёт PROXY protocol (`listen … proxy_protocol`, `xver` в Xray): проверки по
  loopback до него не достанут;
* родитель каталога не принадлежит root или доступен на запись кому-то ещё.

## Архив

**zip** или **tar.gz** — тип определяется по первым байтам, а не по имени, — до **20 МиБ**
(лимит скачивания Bot API; документ больше бот отклоняет, не скачивая). Root распаковывает
архив в `/var/lib/vpn-bot-site/work/<run>/` (root 0700). До сайта ничего не доходит, пока
**каждая** запись не прошла проверки:

| Правило | Отказ |
|---|---|
| только обычные файлы и каталоги | симлинк, жёсткая ссылка, устройство, FIFO, sparse- или зашифрованный элемент |
| относительный путь из простых имён `[A-Za-z0-9_][A-Za-z0-9._~-]*` | абсолютный путь, `..`, `.`, обратная косая черта, NUL, скрытое имя (`.htaccess`, `.git/`) |
| не глубже 12 уровней, не длиннее 512 символов | глубже или длиннее |
| только статика: `.html .htm .css .js .mjs .xml .txt .svg .png .jpg .jpeg .gif .webp .avif .ico .bmp .woff .woff2 .ttf .otf .eot` | всё остальное (`.php`, `.sh`, файл без расширения) |
| до 1000 файлов, до 16 МиБ каждый, до 64 МиБ в распакованном виде | больше. Байты считаются при чтении, а не берутся из заголовков, поэтому zip/gzip-бомба обрывается |
| каждое имя один раз | имя дважды, файл и каталог с одним именем |
| `index.html` в корне | его нет |

Если всё лежит в одной папке (`site/index.html`, …), она разворачивается. `__MACOSX/`,
`.DS_Store` и `Thumbs.db` пропускаются. Файлы пишутся 0644, каталоги 0755, `root:root`;
права и владельцы из архива игнорируются.

Бот кладёт документ в `/run/vpn-bot/site/upload.bin` (его RuntimeDirectory, 0600). Параметр
запуска `digest` — первые 16 hex sha256 документа (16, потому что более длинная hex-строка
для `utils/redact.py` выглядит как секрет). План открывает каталог с `O_NOFOLLOW`, а файл —
относительно него и тоже с `O_NOFOLLOW`. Он берёт upload, только если его sha256 начинается
с этого digest, копирует его в каталог запуска и удаляет копию бота. Дальше ничто не читает
то, что может изменить бот. Поэтому `HELPER_STAGING_ROOT` должен оставаться `/run/vpn-bot`,
как и для staging xray.

## Запуск

Режим `site` (helper `scripts/wizard/vpn-bot-wizard-site`, root-helper `scripts/vpn-bot-site`;
оба в `OUT_OF_REPO_HELPERS` как required на main и в `INSTALL_HELPERS`). Параметры —
`action` (`deploy` | `revert`) и `digest`. Режим dangerous: TOTP перед планом и перед
применением. Контракт мастера ([wizard.ru.md](wizard.ru.md)):

| Шаг | Что |
|---|---|
| **plan** | Сначала `vpn-bot-site recover`: apply, чей юнит убили, откатывается (из-за lock мастера открытый журнал не принадлежит живому запуску). Затем план: архив распакован и проверен; **diff** (файлы `+` / `−` / `~`, страницы до → после); пул spiderX до → после и сколько ключей за ним последует; сохранённые версии (какая уйдёт); как сайт видит Hysteria2. План также проверяет self-steal **до** изменения (nginx активен, ALPN h2 и сертификат домена, `GET /`). Сломанный сертификат блокирует план — иначе проваленный verify откатил бы сайт, который был не виноват. sha256 плана записывается. |
| **apply** | План считается заново; другой sha256 (изменился сайт, архив или пул) — отказ, ничего не меняется. Дальше три шага с журналом. **site_stage**: новое дерево рядом с каталогом (`/var/www/.<имя>.vpn-bot-site-<run>`). **site_swap**: один `renameat2(RENAME_EXCHANGE)` двух каталогов — nginx отдаёт старый сайт или новый, но никогда не половину каждого. На файловой системе без этого вызова — два rename, и результат об этом говорит. **site_env**: `XRAY_SPIDER_X_POOL` в `.env` — сначала бэкап, владелец и права сохраняются, остальные строки побайтно. Упавший шаг откатывает все шаги. |
| **verify** | Каталог — запланированное дерево; nginx активен; ALPN h2 и сертификат домена (`openssl s_client`, SNI = домен); **`GET /` и каждая страница отвечают 200 по HTTP/2** (`curl --resolve <домен>:8443:127.0.0.1`, одно соединение на 40 страниц); пул — запланированный. Если всё зелёное — **commit**: заменённое дерево сохраняется (`/var/lib/vpn-bot-site/releases/<UTC>-<sha12>/`, последние **5**), `state.json` записывает, что живое. Если пул изменился, `vpn-bot-subscription` и бот перезапускаются, чтобы его прочитать (бот — `--no-block`: о запуске отчитывается новый процесс). |
| **rollback** | Журнал в обратном порядке: старое дерево на месте, `.env` и `state.json` как были. Это покрывает и проваленный verify, и проваленный commit. |

Ни один шаг не трогает сеть, конфигурацию nginx или сертификат, поэтому dead-man не
взводится. Шаг, превысивший таймаут, runner убивает и откатывает.

**Сохранённые версии.** Выкладка сохраняет заменённое дерево как *previous*. «Откатить»
возвращает новейшую *previous* и сохраняет откаченное дерево как *rolled back*: второй
«Откатить» уходит ещё на версию назад, а не вперёд. Сайт, сделанный руками, сохраняется как
любой другой: первая выкладка на проде сохраняет бывший там сайт — с симлинками, правами и
владельцами.

## spiderX следует за сайтом

spiderX в REALITY — путь, который «паук» клиента запрашивает у настоящего сайта. Путь,
которого на сайте нет, ответил бы 404 — уже сам по себе признак. Пока `XRAY_SPIDER_X_POOL`
**используется** (не пуст), выкладка ставит в него **страницы нового сайта**: `/`, каждый
`*.html` и `dir/` для `dir/index.html` — не больше 64, только безопасные символы. Путь,
которого на новом сайте нет, из пула уходит. **Пустой пул остаётся пустым**: выключенный spx —
выбор оператора, и выкладка его не включает. Пул, который уже точно равен страницам нового
сайта, не переписывается.

После успешного запуска бот (единственный, кто пишет в базу) даёт каждому xray-ключу, чей
**сохранённый** `vpn_keys.spider_x` больше не в пуле, то значение, которое получил бы новый
ключ (`utils.spider_x.pick_spider_x`: SHA-256 его UUID по новому пулу). Ключ, чьё значение
осталось в пуле, его сохраняет, и его ссылка не меняется. Отчёт говорит, сколько ключей
переехало. План их уже считает: helper читает базу только на чтение (`mode=ro`). Ротация
детей подписки (`XRAY_SPIDER_X_ROTATION_HOURS`) вычисляется из пула при отрисовке ссылки,
поэтому следует за ним после перезапуска.

Backfill при каждом старте — **не** этот шаг. Он заполняет только NULL в `spider_x` и
никогда не перезаписывает проставленное значение (`tests/test_schema_upgrade_row_fidelity.py`).
Переразложение — явное следствие запуска «Сайт». Ручная правка `XRAY_SPIDER_X_POOL` по-прежнему
ничего не переразлагает.

## Hysteria2

С поставляемым `masquerade.type: proxy` на `https://127.0.0.1:8443` Hysteria2 показывает тот
же сайт, и зеркалить нечего. Хост с `type: file` читает свою копию: план предупреждает, что
новый сайт попадёт туда только через `deploy/vpn-bot-decoy-freshen.sh` (его cron зеркалит
каталог).

## Файлы

| Путь | Что |
|---|---|
| `/usr/local/sbin/vpn-bot-site` | root-helper: `status`, `plan deploy\|revert`, `apply`, `verify`, `commit`, `rollback`, `recover` |
| `/usr/local/sbin/vpn-bot-wizard-site` | helper режима мастера |
| `/var/lib/vpn-bot-site/state.json` | 0644: что живое (дерево, архив, когда, каким запуском) и что сохранено |
| `/var/lib/vpn-bot-site/journal.json` | 0600: последний apply по шагам |
| `/var/lib/vpn-bot-site/releases/<id>/` | 0700: сохранённые деревья |
| `/var/lib/vpn-bot-site/work/<run>/` | 0700: архив запуска, его распакованное дерево, план, бэкап `.env`. Удаляется в конце запуска; каталог отменённого плана уходит со следующим планом |
| `/run/vpn-bot/site/upload.bin` | копия документа у бота, пока её не забрал план |
| `/var/log/vpn-bot-site.log` | лог helper'а (с редактированием секретов) |

Новых файлов конфигурации хоста нет, поэтому `MANAGED_HOST_FILES` не меняется. Пример
sudoers даёт боту ровно `/usr/local/sbin/vpn-bot-site status --json`; любое изменение идёт
через `vpn-bot-wizard launch`.

## Тесты

`tests/test_site_helper.py` (root-helper на фейковом хосте: каждый злой архив отклонён, и
ничего не изменилось; выкладка / сохранение / откат; каждый упавший шаг, проваленный verify
или commit откатываются — с `RENAME_EXCHANGE` и без; пул следует за сайтом),
`tests/test_wizard_site_mode.py` (режим через launcher) и `tests/test_site_bot.py` (экран,
загрузка, переразложение — в том числе на базе, обновлённой со свежего снапшота прода). Сети
нет: `curl`, `openssl` и `systemctl` — заглушки (`tests/site_fakes.py`).
